## ✨ About PITLABS

**PITLABS** adalah aplikasi web yang dirancang untuk mendukung pengelolaan penyewaan perangkat AI, IoT, komputasi, dan teknologi lainnya. Platform ini menyediakan katalog produk, informasi ketersediaan, serta antarmuka pengelolaan penyewaan bagi pelanggan dan administrator.

PITLABS dikembangkan untuk membuat proses pemesanan perangkat lebih terstruktur dibandingkan proses manual melalui percakapan. Alur penyewaan yang dirancang meliputi:

<div align="center">

`Jelajahi Katalog` &nbsp; → &nbsp; `Cek Ketersediaan` &nbsp; → &nbsp; `Ajukan Penyewaan` &nbsp; → &nbsp; `Pembayaran` &nbsp; → &nbsp; `Pengambilan` &nbsp; → &nbsp; `Pengembalian`

</div>

Untuk produk yang tersedia untuk dibeli, halaman detail dapat mengarahkan pengguna ke marketplace eksternal. PITLABS tidak memproses pembayaran pembelian produk tersebut.

## ⚙️ Requirements

Pastikan lingkungan pengembangan sudah memiliki:

- PHP **8.2 atau lebih baru** (cek dengan `php -v`).
- Composer.
- **MySQL atau MariaDB** (misalnya melalui XAMPP).
- Ekstensi PHP: `mbstring`, `openssl`, `fileinfo`, `curl`, `zip`, dan `pdo_mysql`. Untuk menjalankan tes, aktifkan juga `pdo_sqlite`.
- Browser modern.
- Koneksi internet untuk memuat Bootstrap dan font dari CDN.

> PHP 8.0 belum memenuhi persyaratan minimum aplikasi.

## 📦 Installation & Setup

Panduan ini mengikuti paket source PITLABS yang ditempatkan ke dalam instalasi Laravel baru.

### 1. Create a Laravel project

```bash
composer create-project laravel/laravel pitlabs
cd pitlabs
```

### 2. Add PITLABS source

Salin isi source PITLABS ke direktori utama proyek Laravel yang baru dibuat dan pilih **timpa** untuk file yang sama. Pertahankan file konfigurasi lokal seperti `.env` apabila sudah tersedia.

> **Memperbarui dari paket Fase 4 (simulasi)?** Hapus file lama `app/Support/DemoAuth.php` dan `app/Http/Middleware/DemoRole.php`. Keduanya sudah digantikan autentikasi Laravel.

### 3. Create the database

Jalankan **MySQL** melalui XAMPP Control Panel (Apache tidak wajib), lalu buka phpMyAdmin dan buat database:

| Setting | Value |
|---|---|
| Database name | `pitlabs` |
| Collation | `utf8mb4_unicode_ci` |

### 4. Configure environment

Buat file `.env` dari template hanya jika belum tersedia, lalu buat application key:

```bash
# Jalankan hanya jika file .env belum tersedia
cp .env.example .env
php artisan key:generate
```

Atur konfigurasi lokal berikut pada `.env`:

```env
APP_NAME=PITLABS
APP_ENV=local
APP_URL=http://127.0.0.1:8000

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=pitlabs
DB_USERNAME=root
DB_PASSWORD=

# Opsional: akun admin awal. Jika ADMIN_PASSWORD kosong, kata sandi dibuat
# acak dan ditampilkan satu kali di terminal saat seeding.
ADMIN_EMAIL=admin@pitlabs.test
ADMIN_PASSWORD=
```

> File `.env` berisi konfigurasi lokal dan rahasia. Jangan melakukan commit file ini ke repository.

### 5. Migrate and seed the database

```bash
php artisan migrate --seed
```

Perintah ini membuat tabel `users`, `categories`, `products`, dan `inventory_units`, lalu mengisi 2 kategori, 7 produk resmi (tanpa harga dan spesifikasi), 15 unit contoh, serta akun admin. Pada `APP_ENV=local` dibuat pula akun pelanggan contoh `pelanggan@pitlabs.test`.

> **Catat kata sandi akun yang tampil di terminal.** Kata sandi yang dibuat acak hanya ditampilkan satu kali.

### 6. Run the application

```bash
php artisan optimize:clear
php artisan serve
```

Buka aplikasi melalui browser:

- **Login:** [http://127.0.0.1:8000/masuk](http://127.0.0.1:8000/masuk)
- **Register:** [http://127.0.0.1:8000/daftar](http://127.0.0.1:8000/daftar)
- **Design System:** [http://127.0.0.1:8000/design-system](http://127.0.0.1:8000/design-system) — hanya tersedia ketika `APP_ENV=local`.

Masuk dengan akun admin hasil seeding untuk membuka `/admin`, atau daftarkan akun pelanggan baru untuk membuka `/dashboard`. Pelanggan tidak dapat membuka area admin.

## 🧪 Testing

```bash
php artisan test
```

Pengujian autentikasi dan otorisasi berada pada `tests/Feature/AuthTest.php` dan memakai SQLite in-memory, sehingga tidak menyentuh database MySQL. Cakupan saat ini: registrasi, login berhasil dan gagal, akun nonaktif, pencegahan penyisipan peran admin, pembatasan akses `/admin`, pengalihan tautan eksternal, logout, serta pengelolaan akun pelanggan oleh admin.

## 🗂️ Project Structure

```text
app/
├── Http/
│   ├── Controllers/       # Publik, katalog, ketersediaan, auth, pelanggan, dan admin
│   └── Middleware/        # EnsureRole: otorisasi berdasarkan peran
├── Models/                # User, Category, Product, InventoryUnit
└── Support/               # Helper (Pit) dan data contoh (MockCatalog, MockAvailability, MockData)

config/
└── pitlabs.php            # Konfigurasi identitas, navigasi, dan label status

database/
├── migrations/            # Skema: users, categories, products, inventory_units
└── seeders/               # Kategori, produk resmi, unit contoh, dan akun awal

resources/
└── views/
    ├── layouts/
    ├── partials/
    ├── components/
    ├── pages/
    ├── catalog/
    ├── auth/
    ├── admin/
    └── dashboard/

public/
└── assets/
    ├── css/               # Stylesheet aplikasi
    └── js/                # JavaScript aplikasi

tests/
└── Feature/               # Pengujian autentikasi dan otorisasi

docs/                      # Dokumentasi proyek
```

## 🏗️ Application Flow

```text
              Browser
                 │
                 ▼
          Laravel Routes
                 │
        ┌────────┴─────────┐
        │ auth + EnsureRole│   ← peran CUSTOMER / ADMIN
        └────────┬─────────┘
                 ▼
            Controllers
        ┌────────┴──────────────┐
        ▼                       ▼
 Eloquent · MySQL         Mock Data Layer
 (users, categories,      (katalog, ketersediaan,
  products, units)         pesanan, antrean, laporan)
        └────────┬──────────────┘
                 ▼
            Blade Views
                 │
                 ▼
      Bootstrap · CSS · JS
```

Autentikasi dan data akun sudah memakai database. Fitur lain masih memakai lapisan data contoh (`app/Support`) agar alur antarmuka dapat dicoba. Pada tahap berikutnya, lapisan tersebut digantikan secara bertahap oleh model dan database tanpa mengubah tampilan.
